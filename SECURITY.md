# Security Policy

## Supported versions

Only the `main` branch and the images built from it are supported. Images are
rebuilt weekly so they pick up base image and package security updates; pull
the latest `ubuntu26.04` or `ubuntu24.04` tag (or the matching digest) to stay
current.

| Image variant        | Base image   | Bareos packages                           |
| -------------------- | ------------ | ----------------------------------------- |
| `*-ubuntu26.04`      | Ubuntu 26.04 | download.bareos.org/current (stable branch) |
| `*-ubuntu24.04`      | Ubuntu 24.04 | download.bareos.org/current (stable branch) |

Older tags are not patched.

## Reporting a vulnerability

Please do **not** open a public issue for security problems.

Use [GitHub private vulnerability reporting](../../security/advisories/new)
for this repository. Include the affected image tag or digest, a description
of the issue and, if possible, steps to reproduce.

You can expect an acknowledgement within 7 days. Confirmed issues are fixed on
`main`, published as new image tags and mentioned in the release notes.

Vulnerabilities in Bareos itself should be reported to the Bareos project:
<https://www.bareos.com/security/>.

## What this project does to stay secure

- All base images and GitHub Actions are pinned by digest/commit and updated
  by Renovate.
- Every image is scanned with Trivy before it is pushed; fixable `CRITICAL`
  findings fail the build. Published images are re-scanned daily.
- Images are signed with cosign (keyless) and shipped with SBOM and
  provenance attestations.
- `gitleaks`, `shellcheck` and `hadolint` run in pre-commit and CI.
- Passwords generated by the Bareos packages at build time are rotated on
  the first container start, so containers never share image-baked secrets.
